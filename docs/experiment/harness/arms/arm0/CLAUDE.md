# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Monica is an open-source personal relationship manager (PRM). This is the `main` branch — the in-development beta rewrite. The stable version lives on the `4.x` branch. Stack: Laravel 12 (PHP 8.3+), Inertia.js 2 + Vue 3, Tailwind 4, Vite 7, Jetstream/Fortify auth, Sanctum API, Scout search (Meilisearch/Typesense/collection), Sabre for CardDAV/CalDAV. Tool versions are pinned in `.tool-versions` (PHP 8.3, Node 22, Yarn 4.6).

## Commands

```bash
# Frontend
yarn dev                 # Vite dev server
yarn build               # client + SSR build
yarn lint                # eslint
yarn format              # prettier

# PHP formatting / static analysis
vendor/bin/pint          # code style (runs on staged *.php via husky/lint-staged)
vendor/bin/phpstan       # larastan; this is what CI runs on PRs

# Tests (PHPUnit; tests/Unit and tests/Feature form a single "Unit" suite)
php artisan migrate:fresh --database=testing && php artisan db:seed --database=testing   # one-time DB prep
vendor/bin/phpunit
vendor/bin/phpunit tests/Unit/Domains/Contact/ManageNotes/Services/CreateNoteTest.php
vendor/bin/phpunit --filter it_creates_a_note
vendor/bin/paratest      # parallel
```

Tests use the `testing` DB connection (defaults to SQLite at `database/database-test.sqlite`, override with `DB_TEST_*` env vars). Tests use `DatabaseTransactions`, not `RefreshDatabase`, so the testing DB must be migrated and seeded before running tests. CI runs against sqlite, mysql and pgsql on PHP 8.3 and 8.4 (see `tests/.env.ci.*`).

PR titles must follow Conventional Commits (enforced by `semantic.yml`; releases are generated by semantic-release).

## Architecture

### Domain-organized code (`app/Domains`)

Most business logic lives in `app/Domains/{Area}/{Feature}/`, e.g. `app/Domains/Contact/ManageNotes/`. Top-level areas are `Contact`, `Settings`, `Vault`, etc. Each feature folder usually contains:

- `Services/` — one class per write operation (`CreateNote`, `UpdateNote`, `DestroyNote`).
- `Web/Controllers/` — thin controllers that build a `$data` array (always including `account_id`, `author_id`, `vault_id`, and so on from `Auth` and route params), call `(new SomeService)->execute($data)`, and return either an Inertia page or JSON.
- `Web/ViewHelpers/` — static classes (`data()`, `dto()`) that turn models into the arrays sent to Vue, including URLs built with `route()`.
- Sometimes `Jobs/`, `Events/`, or `Api/`.

Tests mirror this layout under `tests/Unit/Domains/...`, with one test per service and one per view helper.

### Services (`app/Services/BaseService.php`)

All mutations go through services that extend `BaseService` and implement `ServiceInterface`:

- `rules()` returns Laravel validation rules for the `$data` array.
- `permissions()` returns string keys such as `author_must_belong_to_account`, `vault_must_belong_to_account`, `author_must_be_vault_editor`, and `contact_must_belong_to_vault`. `validateRules()` checks these and fills `$this->author`, `$this->vault`, `$this->contact`, and `$this->group`. Permissions depend on each other; for example, `author_must_be_vault_editor` also needs `vault_must_belong_to_account` and `author_must_belong_to_account`. A missing dependency or unknown key throws an exception.
- `execute(array $data)` calls `$this->validateRules($data)` first.
- `QueuableService` is a variant that can be dispatched as a queued job.

Service tests usually cover the happy path plus `ValidationException`, `ModelNotFoundException` (wrong account/vault/contact), and `NotEnoughPermissionException` (insufficient vault permission). `Tests\TestCase` provides `createUser()`, `createVault()`, and `setPermissionInVault()`.

### Tenancy model

Account → Users and Vaults. Users get access to vaults through a pivot table with a numeric permission (`Vault::PERMISSION_MANAGE` < `PERMISSION_EDIT` < `PERMISSION_VIEW`; a lower number means more rights). Contacts, groups, journals, and similar records belong to a vault. Routes in `routes/web.php` are nested under `vaults/{vault}/...` and protected by gate middleware (`can:vault-viewer,vault`, `can:contact-owner,vault,contact`, `can:vault-manager,vault`, etc.). Many IDs are UUIDs.

### Frontend

Inertia pages are resolved from `resources/js/Pages/**` (see `resources/js/app.js`) and rendered with SSR (`resources/js/ssr.js`). Components receive data shaped by the ViewHelpers. Routes come from Ziggy (`route()` is available in components). Translations use `laravel-vue-i18n` and load from `lang/*.json`. Use `php artisan monica:localize` to regenerate locale files.

### DAV

CardDAV/CalDAV servers live in `app/Domains/Contact/Dav` (vCard/vCalendar import/export, Sabre backends). The client that syncs remote address books lives in `app/Domains/Contact/DavClient`.
